01

01 — 일하는 방식

기능 하나를 에이전트와 만드는 6단계

  • 적용 대상: SPOS 서버(커밋 1,700+) · 테스트 콘솔 Flow Lab. 구현의 상당 부분을 Claude Code · Codex로 진행
  • 출발점: 에이전트는 세션마다 기억이 리셋되고, 정하지 않은 부분은 추측으로 채움
  • 그래서: 프롬프트 요령 대신 용어 · 구조 · 계약 · 검증을 저장소와 이슈에 고정

단계 · 하는 일 · 효과

  1. 용어집 mattpocock skills의 domain-modeling으로 서비스 용어를 GLOSSARY.md에 정리. 개념마다 승인 용어 1개 + 쓰지 않는 말을 함께 기록하고, 큰 결정은 ADR로 남김. 예: ‘정정’과 ‘수정’을 서로 다른 개념으로 고정 → 사람 · 에이전트 · 클라이언트 · 코드가 같은 단어를 씀 → 요구사항 오해와 이름 불일치 감소
  2. 폴더 규칙 기능보다 폴더 구조를 먼저 설계. 폴더 · 파일마다 책임을 정함: 컨트롤러는 트랜잭션 소유 금지, 판정 모듈은 DB · HTTP import 금지, 라우터 등록은 선언 테이블 한 곳. 규칙은 AST 구조 테스트로 강제 → 문제가 터진 위치를 보면 열어 볼 파일이 정해짐 → 에이전트 탐색 범위 축소, 규칙 위반은 CI에서 차단
  3. 계약 확정 이슈 발행(범위 · 완료 조건). 첫 구현이면 요청 · 응답 스키마와 API 초안을 들고 클라이언트와 협의 → 문제를 찾으면 설계부터 수정 → 확정 후 구현 착수 → 수정이 코드가 아니라 문서 단계에서 끝남 → 재작업 감소, 에이전트가 추측할 공백 제거
  4. 구현 이슈 단위로 에이전트에 위임. 착수 전 흐름표(요청 → 권한 · lock → DB 변경 → side effect → 응답 · 에러)를 한글 의사코드로 승인, 호출자 · 형제 경로 영향 조사 → 코드 전에 이해를 검증 → 같은 기준을 쓰는 경로를 한 번에 수정, 누락 감소
  5. 리뷰 · 시나리오 show-me로 변경점(diff · 호출 흐름 · 화면)을 눈으로 확인 → code-review 스킬로 리뷰 → Playwright로 실제 사용자 시나리오를 작성 · 실행 → “다 됐습니다” 보고 대신 확인된 변경점과 시나리오 결과로 완료 판정
  6. 연동 · 배포 테스트 콘솔 Flow Lab으로 클라이언트 연동 전에 연동 · 실사용 테스트 → 클라이언트 연동 → 서버 반영 → 클라이언트와 붙는 시점에 남은 수정 최소화
