## 2. 왜 자동화가 필요했는가

ERP 엑셀은 사람이 화면에서 확인하기에는 충분하지만, 그대로 부과내역서·재무제표·전표 입력에 쓰기에는 구조가 맞지 않는 경우가 많았습니다. 같은 금액도 산출물마다 필요한 컬럼명과 집계 기준이 달랐고, 항목명이 조금씩 다르거나 빈 셀이 섞이면 사람이 다시 확인해야 했습니다.

그래서 자동화의 기준을 “엑셀 변환”이 아니라 “업무자가 마지막에 확인해야 하는 위험을 줄이는 것”으로 잡았습니다.

  <strong>표기 차이</strong><span>같은 의미의 항목도 ERP 원본, 내부 보고 양식, 전표 입력 양식에서 이름이 다르게 쓰일 수 있었습니다.</span>
  <strong>금액 검증</strong><span>총액, 세부 항목 합계, 차감 금액이 맞는지 사람이 눈으로 다시 확인해야 했습니다.</span>
  <strong>전표 입력 오류</strong><span>최종 전표 입력은 사람이 처리하기 때문에 계정과목, 적요, 차변/대변 방향, 금액 부호가 흔들릴 수 있었습니다.</span>

</div>

## 3. 어떤 방식으로 처리했는가

### 산출물을 먼저 고정

원본 ERP 파일 구조부터 코드로 바로 처리하지 않고, 실제 업무에서 필요한 결과물을 먼저 분리했습니다. 부과내역서는 세대별로 볼 수 있어야 하고, 재무제표 확인용 표는 계정과목과 금액 합계가 맞아야 하며, 전표 입력용 데이터는 입력 순서와 필수 컬럼이 더 중요했습니다.

이렇게 산출물 기준을 먼저 잡아두면, 원본 엑셀 컬럼이 바뀌어도 “무엇을 만들어야 하는지”가 흔들리지 않습니다.

### 원본 컬럼을 업무 필드로 매핑

ERP 원본의 헤더명을 그대로 믿지 않고, 업무에서 사용하는 기준 필드로 다시 매핑했습니다. 예를 들어 부과월, 동/호, 계정과목, 부과 항목, 금액, 적요처럼 후속 산출물에서 반복적으로 쓰이는 필드를 중심으로 정리했습니다.

<div className="portfolio-table-scroll">

| 업무 필드 | 확인한 내용 | 처리 기준 |
| --- | --- | --- |
| 부과월 | 파일명, 시트명, 원본 컬럼 중 어디에 기준 월이 있는지 확인 | 산출물 전체에 동일 기준 월 적용 |
| 세대 정보 | 동, 호, 세대명 표기가 섞일 수 있음 | 동/호 기준으로 정렬 가능한 형태로 정리 |
| 계정과목 | ERP 항목명과 전표 항목명이 다를 수 있음 | 매핑 테이블 기준으로 표준 항목명 부여 |
| 금액 | 부과, 차감, 합계 컬럼이 분리될 수 있음 | 숫자형 변환 후 합계 검증 대상으로 분리 |
| 적요 | 전표 입력에서 필요한 설명 문구 | 자동 생성하되 사람이 확인 가능한 형태로 유지 |

</div>

### 검증 규칙을 산출물보다 먼저 실행

결과 파일을 만든 뒤 사람이 오류를 찾는 방식이 아니라, 변환 중간 단계에서 검증 결과를 먼저 분리했습니다. 필수값이 비어 있거나, 금액 합계가 맞지 않거나, 매핑되지 않은 항목명이 있으면 산출물 생성 전에 확인 대상으로 남기는 방식입니다.

  </div>
  <div>

  </div>
  <div>
    <strong>전표 입력 규칙 확인</strong>

  </div>
</div>

### 전표 입력 방식을 규칙화 <span id="voucher-rules"></span>

자동화 결과가 있어도 마지막 전표 입력 과정은 사람이 처리하기 때문에 휴먼 에러가 남을 수 있습니다. 특히 같은 항목을 입력하더라도 담당자마다 계정과목명, 적요 문구, 금액 부호, 차변/대변 방향을 다르게 입력하면 이후 ERP 원본 자체가 다시 오염된 데이터가 됩니다.

그래서 전표 입력을 “개별 담당자의 판단”에 맡기지 않고, 앞으로 같은 종류의 전표는 같은 방식으로 입력하도록 규칙을 정리했습니다. 자동화는 과거 데이터를 정리하는 데서 끝나지 않고, 이후 생성될 데이터가 덜 흔들리도록 입력 기준을 만드는 방향으로 이어졌습니다.

<div className="portfolio-table-scroll">

| 입력 항목 | 발생할 수 있는 휴먼 에러 | 정리한 입력 규칙 |
| --- | --- | --- |
| 계정과목 | 같은 항목을 서로 다른 계정명으로 입력 | 항목별 표준 계정과목을 정하고 예외 항목은 별도 확인 대상으로 분리 |
| 적요 | 담당자마다 문구가 달라 검색과 집계가 어려움 | 기준 월, 항목명, 대상 정보를 같은 순서로 적는 형식 사용 |
| 금액 부호 | 차감/환급/취소 금액의 부호가 뒤섞임 | 부과, 차감, 환급 유형별 금액 부호 기준을 고정 |
| 차변/대변 | 전표 방향을 잘못 입력해 합계가 어긋남 | 전표 유형별 차변/대변 방향을 표로 정리 |
| 예외 처리 | 애매한 항목을 임의로 입력 | 자동 입력하지 않고 확인 대상 목록에 남기는 방식 적용 |

</div>

### 결과 파일을 목적별로 분리

하나의 큰 엑셀 결과물에 모든 데이터를 넣지 않고, 확인 목적에 따라 결과를 나눴습니다. 부과내역서는 세대별 확인, 재무제표 확인용 표는 계정과목별 합계, 전표 입력용 데이터는 입력 순서와 필수 컬럼을 기준으로 구성했습니다.

<div className="portfolio-table-scroll">

| 결과물 | 목적 | 사람이 최종 확인하는 지점 |
| --- | --- | --- |
| 부과내역서용 데이터 | 세대별 부과 항목과 금액 확인 | 특정 세대 누락, 항목별 금액 이상치 |
| 재무제표 확인용 표 | 계정과목별 합계와 보고 기준 확인 | 계정과목 합계, 전월/당월 차이 |
| 전표 입력용 데이터 | 회계 전표 입력 형식으로 정리 | 차변/대변 성격, 적요, 입력 순서 |
| 검증 리포트 | 자동화가 판단하지 않고 남겨둔 확인 대상 | 매핑 실패, 합계 불일치, 필수값 누락 |

</div>
